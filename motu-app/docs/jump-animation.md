# 跳躍動畫 (Jump Animation)

改跳躍、加新的空中動作、或換玩家模型之後跳躍看起來怪怪的，看這一份。

程式在兩個檔案：

| 檔案 | 負責 |
|---|---|
| `src/components/Three/jumpPose.ts` | **整個跳躍**：狀態機、物理、五個姿勢、混合權重。純函數，不碰 three.js / React |
| `src/components/Three/Avatar.tsx` | 接線：每幀呼叫一次狀態機，把結果寫進 root 與 joint |

驗證：`npm run audit:jump`

---

## 一、原本壞在哪裡

原本的跳躍**沒有動畫**。有的是一段弧線：

```
sin(progress * PI) * 1.9   // 固定 0.4 秒
```

外加 root 的 squash / stretch。而且這段數學在 Avatar.tsx 裡**寫了兩次**（移動分支一次、
站立分支一次）。

四肢完全沒有被寫過。手臂與腿的動畫鏈只在 `isFlipping`、`emote`、游泳姿勢之間分支，
從來沒有「跳躍」這個 case —— 所以角色是**帶著走路的擺手離地**的。
這就是回報的現象：「整個模型被直接往上移動」。

量化的講法（`npm run audit:jump` 會印出來）：舊跳躍在整個過程中的關節總位移是 **0.00 rad**。
現在是 **14 rad**。

## 二、五個階段

```
grounded ──(按下空白鍵)──> crouch ──> takeoff ──> rise ──> fall ──> land ──> grounded
                                                    ↑                ↑
grounded ──(腳下的地面消失)────────────────────────────┘                │
                                              (連續跳躍：緩衝的下一跳) ─┘
```

| 階段 | 中文 | 在做什麼 | 時間 |
|---|---|---|---|
| `crouch` | 準備 | 還踩在地上，下蹲蓄力，手臂向後 | 0.09 s |
| `takeoff` | 起跳 | 已離地，腿伸直、手臂向上擺 | 0.14 s |
| `rise` | 上升 | `vy > 0`。單膝提起、另一腿在後、手臂張開平衡 | 到最高點 |
| `fall` | 下降 | `vy < 0`。手臂張得更開、雙腳收到身體下方；最後 0.1 秒伸腿準備著地 | 到落地 |
| `land` | 落地 | 從觸地當下的姿勢屈膝吸震，然後把身體交還給走路 / 待機 | 0.24 s |

### 空中姿勢跟著 `vy` 走，不是跟著碼表走

`rise` / `fall` 的姿勢是 `vy` 的連續函數（`jumpPose.ts` 的 `flightPose`）：

```
u = vy / 起跳速度        +1 剛離地 → 0 最高點 → -1 落地速度
姿勢 = 下降姿勢 ↔ 上升姿勢，依 u 混合     最高點剛好一半一半 = 滯空感
最後 LAND_REACH_TIME (0.1 s)，依弧線算出的「距離觸地還有幾秒」混入 著地準備（REACH_POSE）
```

舊版是「上升姿勢花 0.12 秒淡入後定住、下降姿勢花 0.15 秒淡入後定住」，所以最高點過後一點點
跟快落地時是同一個姿勢，不管身體下降得多快。squash/stretch 也一樣改成跟速度走：離地時最拉長、
最高點略圓、下降加速時再拉長一點。

`land` 從**觸地那一幀實際的姿勢、權重與拉伸**開始（`entryPose` / `entryWeight` / `entryStretch`），
不是從固定的下降姿勢、滿權重開始：短距離落下（權重還沒淡入到 1）落地不會跳變，落地的 squash
也不會在一幀內從拉長切到壓扁（舊版就是這樣，audit 現在會抓到）。

**準備階段的長度是輸入延遲**。0.09 秒（約五幀）是刻意壓在下限：
再短眼睛看不到，再長玩家會覺得按鍵卡頓。

## 三、動畫與 Physics 同步

弧線是**真的積分出來的**，不是一條 sine：

```
vy 起跳 = 4h/T          h = JUMP_APEX (1.9)
g       = 8h/T²         T = JUMP_AIRTIME (0.46 s)
```

兩個都從高度與滯空時間推導，不各自手調 —— 手調的重力與手調的初速可以對「跳多高」有不同意見，
然後角色就落在弧線說的地方以外。

於是「現在是上升還是下降」不是由碼表回答的，是由 `vy` 的正負回答的，
**落地是弧線碰到地面**，不是計時器歸零。動畫沒有第二份時間軸可以跟物理吵架。

### 畫出來的高度 —— 第二個踩過的坑

狀態機對了，畫面卻還是錯的：Avatar 把**整條弧線**（地面高度 + 跳躍）一起丟進地形用的一階平滑
（`lerp(目前高度, 目標, 10·dt)`，時間常數約 0.1 秒）。對一個 0.46 秒的跳躍，實測：

| 時間點 | 物理 | 畫出來的 |
|---|---|---|
| 離地後 33 ms | 0.48 | 0.10（像被吊起來） |
| 進入 `fall` 時 | 1.90（最高點） | 1.52，**還在往上** |
| 進入 `land` 時 | 0 | **0.78，還在半空** |
| 最高點 | 1.90 | 走路 1.66 / 站著 1.73 |

所以落地吸震和 squash 是在半空中播完的，身體之後才慢慢飄下來；下蹲的 dip 也被抹平了。

現在只有**地面高度（base）**經過平滑，跳躍弧線是之後原封不動加上去的（Avatar 的 `visualLiftRef`、
`characterMovement.ts` 的 `easeBodyBase`）。下一幀讀回 `position.y` 時要先扣掉上一幀加上去的量，
否則它又會被當成地面餵回平滑 —— 這正是舊版「弧線疊加到飛出畫面」那個 bug 的成因，也是
**走路彈跳**的問題：彈跳每幀被讀回，一階延遲的穩態停在 `彈跳 × (1−k)/k`，實測走路時根節點
高出地面 0.64–0.79，而且幀率越高越嚴重。彈跳現在也算成 lift，並在空中隨跳躍權重淡出。

### 地面偵測 —— 一個踩過的坑

第一版用「身體離支撐面多高」來判斷自由落體（走出懸崖邊）。**這是錯的訊號**，而且是實機才問出來的：

繪製用的 root 是用一階延遲去追支撐高度的，所以**走下島上自己的斜坡**時
量到的間距是 **0.79**，比當時 0.45 的門檻高了將近一倍。
角色每次走到海邊都是用下墜姿勢走下去的。

同一個量沒有任何門檻分得開這兩件事。分得開的是**地面是怎麼不見的**：
斜坡是連續下降，速率被玩家的移動速度綁住（這座島最陡的地方約 1 unit/s）；
懸崖是不連續的，一幀之內少掉好幾個單位。

所以：**進入自由落體看的是支撐面的下降速率**（`FREE_FALL_DROP_RATE = 8 units/s`），
間距只用來判斷腳有沒有回到地上。

## 四、姿勢用 joint 名字寫，不寫 ref

五個姿勢都是 `BodyPose`（`constants/interactionPostures.ts`）—— 跟家具互動姿勢**同一套詞彙**：

```ts
const RISE_POSE: BodyPose = {
  head:     { x: -0.06 },
  torso:    { x: -0.04 },
  leftArm:  { x: -0.70, z: -0.45 },
  rightArm: { x: -0.55, z:  0.40 },
  leftLeg:  { x: -0.30 },   // 提起的那隻
  rightLeg: { x:  0.15 },   // 拖在後面的那隻
};
```

寫的是「右手臂在 -0.55」，不是「把 -0.55 寫進 rightArmRef」。

**換模型要做什麼**：手臂拆成上臂 / 下臂的模型，
在 `RigJointName` 加 `leftLowerArm`、在 `CharacterRig` 加對應的 ref，
然後在這五個姿勢裡各加一行。狀態機、物理、混合邏輯都不用動 ——
`applyBodyPose` 是走姿勢自己列出來的 joint，沒提到的關節就完全不碰。

唯一一個跟角色**比例**有關的數字不在姿勢表裡：下蹲時 root 要沉多少。
它是從腿長推出來的（`L(1 − cos θ)`），因為 root 的原點就是**腳底接地點** ——
硬寫一個「下沉 0.10」會把腳直接插進地裡，而且換一個腿長不同的模型就換一個插法。

## 五、優先順序（跟其他動畫的關係）

跳躍姿勢是**疊**在這一幀已經算完的走路 / 待機 / 表情動作上的，權重在兩端都是 0：

```
走路 / 待機 / 表情動作 → 游泳混合 → 【跳躍】 → 互動姿勢
```

- **蓋過** Idle / Walk / Run —— 混合的起點就是身體當下真的在的姿勢，
  所以 Walk→Jump 不需要另外寫過場。
- **不會蓋過**坐 / 躺 / 家具姿勢：那時候 `canJump` 根本不讓跳躍開始。
- **不會蓋過**空翻：兩個全身動畫不能共用一個身體，互相排斥。
- **被游泳淡出**：權重乘上 `(1 - swimPose)`，跳進海裡的那一跳會把身體交給水。
- **在互動姿勢下面**：按 E 用望遠鏡的人應該得到望遠鏡，不是一個跳。

`canJump` 是 Controller 的規則（Avatar.tsx），不是 jumpPose.ts 的：
坐著、躺著、互動中、空翻中、建造模式、更衣室、水深到在游泳 —— 都不准起跳。
它只擋**開始**：已經在空中的跳躍不會被它取消，因為身體不能收回「已經離地」這件事。

## 六、驗證

```bash
npm run audit:jump    # 用真的狀態機跑腳本化的輸入
npm run lint
npm run build
```

`audit:jump` 檢查的是八件事，全部是量出來的不是斷言的：

| 代號 | 抓什麼 |
|---|---|
| `DEAD` | 一次跳躍裡四肢的總位移 ≈ 0（**原本的 bug**） |
| `SNAP` | 任何通道（關節、root、squash/stretch）單幀移動過快，或相對前後幀出現尖峰（不連續 = 「手腳突然跳到另一個姿勢」） |
| `DRAWN` | **畫出來的** root（用 Avatar 同一個 `easeBodyBase` 組出來）跟弧線不一致，或落地那一幀還在空中 |
| `FLOAT` | 週期性的 lift（走路彈跳）被高度平滑累積成漂浮，60 Hz 與 144 Hz 都測 |
| `DESYNC` | 姿勢和物理不同意：`vy < 0` 卻在播上升、人在空中卻已經站好 |
| `STRANDED` | 跳完了姿勢還留在身上（有肢體卡在半空） |
| `SUNK` | 下蹲 / 落地時腳底穿進地面 |
| `HANG` | 跳躍回不到 `grounded` |

情境涵蓋：靜止跳、走路跳、連續跳（按住）、空中預按的緩衝跳、走下斜坡（**不可以**被判成落下）、
從高處落下、從低矮落差踏下（落地時落下姿勢還沒淡入完）、規則不允許時按跳、空中失去跳躍權限、
一次 0.1 秒的掉幀，以及 60 / 144 Hz 的走路彈跳。`DRAWN` / `FLOAT` 另外會印出舊組法的數字作對照
（弧線最多落後 0.79、走路漂浮 0.61 / 1.44）。
