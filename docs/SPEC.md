# SPEC — Island Fitness AI（AI 健身辨識與島嶼建設連動系統）

> 育秀盃創意獎 · AI 應用類 · 可實機 Demo 之網頁應用
> 文件目的：把企劃書（規劃階段）落地為**可執行、可驗證**的產品規格。

---

## 0. 一句話定位
用「一支家裡就有的鏡頭」，把**準教練級的即時動作矯正**帶進居家健身；並以**島嶼建設遊戲**把運動成果視覺化，建立「正確訓練 → 金幣 → 島嶼成長 → 再訓練」的正向循環。

評審視角的核心差異化：**不是計次，而是品質確認**。只有「完整週期 + 達標深度 + 無代償」的動作才算有效次數，才換得到金幣。

---

## 1. 範圍與交付物

### 1.1 平台選型（決策）
- **單頁網頁應用（SPA），純前端、零後端、可離線**。理由：
  - MediaPipe Pose 的 `tasks-vision` WASM 可在瀏覽器以 30+ FPS 跑，直接讀 webcam。
  - Demo 零安裝、跨平台（評審現場用筆電 / 平板開瀏覽器即可）。
  - 所有 AI 模型與函式庫**已 vendor 至本地 `vendor/`，完全離線可跑**（競賽現場網路不可靠）。
  - 資料以 `localStorage` 持久化，無隱私外流、無伺服器成本。

### 1.2 交付物清單
1. 可執行 Web App（`index.html` + `app/` ES Modules）。
2. 核心引擎（pure JS，瀏覽器與 Node 共用）：幾何、正規化、狀態機、防作弊、卡路里、語音教練。
3. 可在 **Node 直接跑的 eval/測試套件**（合成 landmark 序列，零相機）。
4. 流程文件：SPEC / IMPACT / TASKS / CONTRACTS / REVIEW / TRACE。
5. 一鍵啟動腳本（本地 static server）。

### 1.3 明確不做（Demo 邊界）
- 不做雲端帳號 / 跨裝置同步（企劃為「未來」項，本版以本機 localStorage 模擬帳號）。
- 不做真人示範影片庫（以動畫示意圖 + 文字步驟替代）。
- 第三方登入（Google/Apple）僅 UI 占位，不接真 OAuth。

## 2. 系統架構（對應企劃「五層判定防線」）

```
┌─ 互動層 (Interaction) ─ 三色骨架渲染 / 分級語音教練 / 結算報告 / 島嶼遊戲
├─ 邏輯層 (Logic) ─────── 動作狀態機 FSM + 六層防作弊 + 計次冷卻
├─ 標準化層 (Normalize) ─ 肩寬/腿長比例尺 → 動態判定門檻（系統關鍵層）
├─ 辨識層 (Recognition) ─ MediaPipe Pose 33 點 + visibility 信心過濾 + 入鏡檢查
└─ 輸入層 (Input) ─────── webcam 取像 / 鏡頭翻轉 / 多人排除 / 光線提示
```

資料流：`camera frame → PoseLandmarker → 33 landmarks → normalize → exercise FSM → {phase, color, faults, repValid} → coach(voice) + renderer(color) + store(coins/xp/stats)`。

## 3. 四大功能（對應「初步發想計劃」的四顆按鈕，底部 Tab Bar）

| Tab | 名稱 | Icon | 核心職責 |
|----|------|------|---------|
| 1 | 島嶼（遊戲包裝） | 🚀/🏝️ | 用金幣建設島嶼，運動成果視覺化 |
| 2 | 訓練（動作矯正） | 🏋️ | **核心**：AI 即時判定 + 矯正 + 結算 |
| 3 | 健康（追蹤分析） | 📊 | 長期數據圖表、過去 vs 現在對比 |
| 4 | 設定（個人化） | ⚙️ | 帳號/身高體重/偏好/隱私，影響判定與熱量 |

### 3.1 Tab 2 — 訓練（核心流程）
1. **分類選擇**：下肢 / 全身有氧 / 上肢核心 / 臀腿 / 核心；可搜尋。
2. **動作清單**：卡片可上下滑，顯示部位、難度、預估金幣/卡路里。
3. **動作簡介頁**：練哪個部位、每組幾下、休息幾次、共幾組、可得金幣、消耗卡路里、**暖身開關**（開始前帶 1 分鐘暖身）、動作示意動畫。
4. **立即開始** → 底部 tab 自動隱藏，改為「返回鍵」。
5. **偵測主體（最精華）**：
   - 中央：鏡頭畫面 + 即時三色骨架。
   - **倒數邊框**：整個畫面外框是一條會隨時間/組數遞減的光線環。
   - 下方 HUD：暫停 / 退出 / 已運動時間 / 已完成下數 / 消耗卡路里 / 倒數 / 背景音樂開關 / 語音引導開關。
   - 即時：紅黃綠骨架 + 分級語音提示（高優先級可搶佔）。
6. **結算畫面**：運動總額、有效/無效次數、達標率、時間、卡路里、獲得金幣、S/A/B/C 評級、常見錯誤紀錄 →「再一次」或「退出」。

### 3.2 Tab 1 — 島嶼
- 左上：玩家名稱/頭像、等級、XP 進度條、金幣餘額（固定顯示）。
- 左側選單：**造型商店**（建築/裝飾/地塊）、**配備選購**。
- 中央：等距（isometric）格狀島嶼，可放置/移動/收納建築與裝飾。
- 經濟：金幣**只能**來自 Tab 2 的有效訓練（防刷）；建設消耗金幣；達標率高給品質加成。
- 成就：連續訓練 7 天解鎖紀念建築、累積動作數解鎖主題區域。

### 3.3 Tab 3 — 健康
- 數據：運動時長、消耗卡路里、運動頻率、有效次數/達標率、常見錯誤分布。
- 圖表：每日/每週長條圖、卡路里折線趨勢、達標率環圈、錯誤分類圖；**本週 vs 上週**對比。

### 3.4 Tab 4 — 設定
- 帳號（本機）：暱稱、頭像、（占位）第三方登入。
- 個人資料：身高/體重/年齡/性別 → **影響 normalization 門檻與 METs 熱量**。
- 提醒與目標：每日/每週目標、提醒。
- 互動偏好：語音開關、BGM、三色顯示方式、難度、鏡頭視角、鏡像。
- 隱私：資料只存本機、可匯出 JSON、可一鍵刪除（去識別化原則）。

## 4. 動作判定規格（Tool-level）

### 4.1 動作清單（10 項，分 5 群；MVP 完整實作 + 測試前 4 項）
| 群組 | 動作 | 判定關鍵（有效） | 防作弊重點 |
|------|------|-----------------|-----------|
| 下肢 | **深蹲 squat** ✅MVP | 髖低於膝高度、起身回穩 | 排除只彎腰、半蹲 |
| 全身 | **開合跳 jumpingjack** ✅MVP | 手過肩 + 腳超肩寬（1.0–1.2×肩寬） | 排除只揮手、只張腳 |
| 全身 | **高抬腿 highknees** ✅MVP | 膝達髖高、左右交替 | 排除坐著抬腿、不交替 |
| 上肢 | **伏地挺身 pushup** ✅MVP | 手肘下壓達標、身體一直線 | 排除塌腰、撅臀 |
| 下肢 | 弓箭步 lunge | 前膝約 90°、後膝下沉 | 排除半程、不下沉 |
| 全身 | 波比跳 burpee | 蹲→撐→跳完整流程 | 排除省略棒式 |
| 核心 | 仰臥起坐 situp | 軀幹抬起達標、背離地 | 排除只抬頭、甩手 |
| 核心 | 捲腹 crunch | 上背捲起達標 | 排除頸部代償 |
| 臀腿 | 臀橋 glutebridge | 髖上推成線 | 排除只抬腿不推髖 |
| 臀腿 | 側弓步 sidelunge | 橫向跨距 + 深度 | 排除橫移不蹲 |

### 4.2 動作狀態機（每個動作共用骨架）
`IDLE → READY(起始) → CONCENTRIC(發力) → TARGET(達標,亮綠) → ECCENTRIC(回復) → 計次`
- 必須走完整週期才 +1；於 TARGET 不立即計次（防底部停留刷次）。
- 每動作以「主控角度/距離 + 門檻 enter/exit（遲滯 hysteresis）」定義轉移。

### 4.3 六層防作弊（對應企劃 5.3）
1. **完整週期**：缺任何階段不計次。
2. **信心值檢查**：關鍵點 visibility < 門檻（遮擋/多人）→ 暫停判定。
3. **防抖**：移動平均平滑 + 連續 N 幀確認，避免座標跳動誤判。
4. **單肢/同步偵測**：開合跳、波比跳檢查上下肢同步。
5. **代償偵測**：塌腰、身體後仰、只彎腰等 → 標記 fault、不計或降級。
6. **動態冷卻**：計次後 250–500ms 冷卻，避免底部抖動重複計次。

### 4.4 三色視覺反饋
| 色 | 意義 | 觸發 |
|----|------|------|
| 🔴 紅 | 錯誤/無效 | 姿勢錯、關鍵點遺失、完全無效 |
| 🟡 黃 | 接近達標 | 方向對但深度不足/不穩 |
| 🟢 綠 | 達標 | 當前階段達標 |

骨架以「部位」上色：哪段關節違規該段就變色（非整體一色）。

### 4.5 分級語音（搶佔機制）
- 高（安全/看不到全身）可中斷中/低；中（深度/歪斜）；低（節奏/鼓勵）。
- 同句去重 + 冷卻（避免連播）。Web Speech API（zh-TW），無則靜默降級。

## 5. 標準化（系統關鍵層）
- **比例尺**：水平用肩寬 `shoulderWidth = |L_shoulder - R_shoulder|`；垂直用軀幹長/腿長。
- 門檻以比例表示（例：開合跳腳距 ≥ 1.1× 肩寬；深蹲髖 Y ≥ 膝 Y）。
- 角度用三點向量內積：`angle(A,B,C) = atan2 法求 ∠ABC`。
- 個人身高/體重從設定帶入，微調門檻與熱量。

---

## 6. 熱量與評級
- **METs 模型**：`kcal = MET × 體重(kg) × 時間(hr)`。
- MET 值：深蹲 5.4；費力徒手操（伏地挺身/開合跳/仰臥起坐/高抬腿等）8.0。
- 依「達標率」加權，避免高估半程動作。
- **評級**：依達標率 + 有效率 + 強度 → S(≥90%) / A(≥75%) / B(≥60%) / C(<60%)。

---

## 7. 金幣經濟（防刷）
- 基礎：每有效次數 `baseCoinPerRep`（依動作強度）。
- 品質加成：達標率高 ×係數；錯誤多 ×懲罰。
- 連續獎勵：每日任務 / 週目標 / 連續天數。
- 經濟控制：單次/每日獎勵上限，避免刷幣與過度運動。
- **鐵則**：金幣只由「結算結果（已通過 AI 有效判定）」產生，UI 任何按鈕都不可直接加幣。

## 11. 自我 Review（Gate 0）
**優點**：平台選型把「可 demo / 離線 / 可驗證」三者同時滿足；核心邏輯純函式化 → 可在 Node 做確定性測試，這是說服評審「準確率」最硬的證據。
**風險已識別（移交 IMPACT）**：① 相機權限/瀏覽器差異 ② WASM/模型載入大小 ③ 合成 landmark 是否能真實代表動作 ④ 語音 API 相容性。
**結論**：規格自洽、邊界清楚、可驗證。Gate 0 PASS，進入 Gate 1。
