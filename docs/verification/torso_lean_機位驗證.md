# 驗證：深蹲軀幹前傾判定在正面機位是否有效

> 日期：2026-08-28
> 起因：Myer et al. (2014) 的 Back Squat Assessment 明列「軀幹位置」須自**側面**觀察，
> 而本作品深蹲採**正面**機位（企劃書表 4-3、`squat.js` 註解皆然）。
> 結論：**`torso_lean` 在正面機位對矢狀面前傾完全失效，且會對側傾誤報。**

## 一、數學驗證

`vAngleFromVertical(top, bottom)` 的實作（`geometry.js:27`）：

```js
const dx = bottom.x - top.x, dy = bottom.y - top.y;
return Math.atan2(Math.abs(dx), Math.abs(dy)) * RAD2DEG;
```

角度由 **dx（水平位移）** 決定。人繞髖在矢狀面前傾 θ 度時：

| 機位 | 肩的投影位置 | dx | 測得角度 |
|---|---|---|---|
| **正面** | `(hip.x, hip.y − L·cosθ)` | **0** | **0°（恆為零）** |
| 側面 | `(hip.x − L·sinθ, hip.y − L·cosθ)` | `L·sinθ` | θ（正確） |

正面拍攝時，矢狀面旋轉不產生任何水平位移，故 dx 恆為 0。實測：

```
真實前傾角 | 正面機位測得 | 側面機位測得
       10° |        0.00° |       10.00°
       45° |        0.00° |       45.00°
       90° |        0.00° |       90.00°
```

**不論前傾至 90°（整個人對折），正面機位測得皆為 0°，永不觸發 45° 門檻。**

## 二、端對端驗證

取 clean 序列，依正面投影規則施加真實前傾（肩往髖壓縮垂直分量、x 完全不動），餵入引擎：

| 樣本 | 有效 | 無效 | torso_lean |
|---|---|---|---|
| clean（標準） | 5 | 0 | — |
| compensation（合成器版） | 0 | 5 | ✓ 5 次 |
| **正面機位・真實前傾 45°** | **5** | **0** | **✗ 完全沒抓到** |
| **正面機位・真實前傾 60°** | **5** | **0** | **✗ 完全沒抓到** |

## 三、為什麼測試全綠卻功能失效

合成器模擬「彎腰代償」的方式（`synth.js:67`）：

```js
for (const i of [LEFT_SHOULDER, RIGHT_SHOULDER, NOSE, ...]) sk[i].x += lean;
```

**把肩膀往 x 方向（水平）位移——那是「往側邊倒」，不是「往前彎腰」。**
於是引擎測到 46.42°、測試通過。但真人正面彎腰產生的是垂直方向的投影縮短，dx 不變。

這是「用自己寫的合成器驗證自己寫的引擎」的典型後果：
合成器用**錯誤的方式**模擬錯誤動作，引擎於是「通過」了一個它其實不會的測試。

## 四、比漏抓更嚴重的問題

`torso_lean` 在正面機位並非完全不觸發——它會對**側傾與身體旋轉**觸發，
然後對使用者說「背部打直，不要彎腰，用臀部往後坐下」。

**抓到的是 A，說出來的是 B。** 使用者身體稍微歪斜就會收到彎腰警告，且該次被判無效（block 級）。
教練示範影片實測（3 支標準深蹲）torsoLean 峰值為 8.17°／28.68°／26.12°，
其中 28.68° 者若再歪一些即會觸發——而那並不是彎腰。

## 五、可能的處理方向（未實作，待決策）

| 方案 | 說明 | 代價 |
|---|---|---|
| A 改側面機位 | 符合 BSA 建議 | **側面看不到膝內夾**（需正面），深度判定亦須重訂 |
| B 雙機位 | — | 居家單鏡頭不可行 |
| C 使用 MediaPipe 的 z 座標 | 有深度輸出 | 牴觸企劃書已載明之界線：單鏡頭深度估計於居家環境不可靠 |
| **D 改用軀幹投影長度比** | 前傾 θ 時投影長 = L·cosθ，正面可測 | 需記錄站立基準、須重新標定門檻 |
| E 承認限制 | 標明正面機位不判前傾，或降為 advisory | 失去一項判定 |

## 六、處理結果（2026-08-28 當日實作）

採方案 D。改動四處：

| 檔案 | 改動 |
|---|---|
| `engine.js` | 新增站立基準 `standTorso`，只在 progress<0.15（人還站著）時緩慢更新。<br>不能沿用既有的 `scaleEma`（a=0.12，半衰期約 5 幀），否則彎腰持續一秒基準就跟著縮短。 |
| `squat.js` | 判定改為 `torsoRatio < 0.86`（軀幹畫面投影長 ÷ 站立基準）。閘門 progress≥0.15。 |
| `synth.js` | compensation 改為正面投影的真實前傾（壓縮垂直分量、x 不動）。<br>**不修這裡，改完仍無法證明有效** —— 舊版用水平位移模擬彎腰，正是本次缺陷的成因。 |
| 測試 | framing 的兩處注入改為正面投影彎腰（40°）；C-2 鎖值測試改鎖投影比。 |

### 驗證結果（漸進式前傾：站直 → 蹲下時才彎腰，與真人相同）

| 樣本 | 有效 | 無效 | torso_lean |
|---|---|---|---|
| 標準（不彎腰） | 5 | 0 | 不誤殺 ✓ |
| 最深處前傾 30°（正常範圍） | 5 | 0 | 不誤殺 ✓ |
| 最深處前傾 45° | 0 | 5 | **抓到 ✓** |
| 最深處前傾 60°／75° | 0 | 5 | **抓到 ✓** |

修復前同一組測試：45°/60° 皆為 5 次全有效、一次未觸發。

### 新發現的盲區：基準污染

本量測的是「軀幹相對於**自己站姿**的變化」，不是絕對姿勢。
若使用者**從一開始站著就已駝背**，站立基準即在彎腰狀態下建立，比值恆為 1，系統偵測不到。

驗證過程中曾對全序列施加固定前傾（等同「天生駝背」），結果 45°/60° 完全無法偵測，即為此故。

**已據此修正真人測試手冊**：彎腰組的口令必須是「**先站直**，然後用彎腰代替蹲」，
而非「全程駝背做完」。後者是本方法的已知盲區，需另行處理。

### 仍未解決

- 門檻 0.86 為透視模型試算值，**未經真人樣本標定**
- 只分辨得出明顯彎腰（≥45°），30–45° 的輕微前傾仍分不出來
- 完整軀幹評估仍需側面機位（BSA 的建議）
