# 深蹲：站立基準修正（2026-10-16）

> ⛔ **2026-10-16 已撤回**（引擎回到 0bd639d 的版本）。使用者實測：站在筆電前打字時骨架變黃綠，以為在蹲。
> 原因：基準只收「下降量 < 0.05」的幀，小幅姿勢改變（彎腰、靠近筆電）不再被基準吸收，訊號殘留超過顯示門檻 0.10。
> 本文驗證只測了「蹲的時候準不準」，**沒有測非深蹲動作會不會誤觸發**。日後重做必須先補：站著不動、走動、打字、彎腰。

## 起因
使用者實測（M4 Pro MacBook Pro，鏡頭已改原生 4:3）：正面深蹲蹲到大腿約水平，深度條仍停在白線下，整組 0 次。螢幕錄影 76 秒（原檔在使用者下載資料夾，未進 repo）。

## 根因（重播錄影量到的）
`tools/replay/replay.html` 逐格重播，站直時髖下降量（hipDrop）中位 −0.039，個別段落到 −0.12：站立基準比真正站直還低，每一下的下降量因此少算約 0.05–0.1。
1. 基準在 progress < 0.15（約 hipDrop < 0.16）時更新，開始往下蹲的前幾幀也被當成站姿寫進基準。
2. 人一進畫面就開始蹲時，基準從半蹲位置起算，以 0.05 慢慢爬回要好幾秒（錄影 63–66 秒，站直時 hipDrop 為 −0.45～−0.18）。

## 修改
`app/core/engine.js` `updateStandBaseline`：髖、膝基準只收「相對基準下降量 < `STAND_DROP_MAX`（0.05）」的幀；比基準高的幀以 0.2 追上，其餘維持 0.05。門檻 `DROP_GATE` 0.72 未動。

## 結果

真人錄影重播（系統自己的 MediaPipe full 模型＋深蹲判定器）：

| 錄影 | 修改前 | 修改後 | 說明 |
|---|---|---|---|
| 10-16 正面（本次） | 2 有效 | 3 有效 | 站直 hipDrop 中位 −0.039 → +0.013；仍有兩下峰值 0.75、0.72 壓線未過 |
| 10-11 s1 正面 | 14 有效 | 16 有效 | 新增兩下（108 秒斜站、213 秒正面）逐格看最低點都是蹲到底 |
| 10-11 s2 側身（實際 9 次） | 8 有效 | 9 有效 | 補回第 1 下（先前 0.709 壓線） |

UI-PRMD 投影模擬（10 人 × 20 次、腳踝出框，鏡頭高 800／1000／1150mm × 距離 0.6–1.6 倍身高 × 正面／45°／側身）：
- 蹲到底計次：多數正面與 45° 條件上升（例：1000mm、1.0 倍身高正面 55.2% → 96.6%；1150mm、1.2 倍 34.5% → 79.3%）。
- 明確半蹲（髖高於膝 ≥ 100mm）誤計：正面與 45° 全部 0%；**側身由 0% 變為 0.8%（多數條件）、最高 6.3%（800mm、1.6 倍身高）**。

## 已知限制（必須揭露）
- 近距離正面仍計不到：1000mm、0.6 倍身高 0%；1150mm、0.8 倍以內 0%。原因是透視（膝往前靠近鏡頭、畫面上看起來往下移），不是基準問題，本次沒有解決。
- 側身半蹲誤計在模擬上有小幅上升。曾試「側身時門檻提高到 0.80」可壓回 0%，但真人 s2 第 1 下（0.77）會再掉，故未採用。
- 只有一位受試者的真人錄影；模擬資料為雙臂過頭的 FMS 深蹲。

## 重現
```bash
# 影格：ffmpeg 把錄影裁出鏡頭畫面、抽 15fps 放 tools/replay/frames/<名稱>/（不進 repo）
python3 -m http.server 8099   # 專案根目錄
# 開 http://localhost:8099/tools/replay/replay.html?dir=frames/<名稱>&fps=15，結果在 window.__replay
```
新錄影可用 `tools/replay/record.html`（與系統同一支 startCamera，錄鏡頭原始畫面）。
