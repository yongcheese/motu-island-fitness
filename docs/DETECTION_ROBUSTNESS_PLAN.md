# 偵測韌性與「最佳使用模式」設計計畫

## 背景與場景
- 育秀盃 Demo。實機在 **MacBook 內建鏡頭 + 小空間**,評審站在筆電前操作。
- 核心功能 = MediaPipe Pose 即時偵測四個動作:深蹲 / 開合跳 / 高抬腿 / 伏地挺身。
- 純前端、離線、無後端。引擎為純函式 (`app/core/`),34 個確定性單元測試。

## 問題(實機回報,嚴重)
- 真實使用時「人在畫面中比例太大」,常只偵測到上半身;**離 2 公尺也一樣**。
- 結果:整個判定停擺,使用者完全做不了動作。
- 兩個疊加成因:
  1. **硬體/系統**:macOS「人物置中 / Center Stage」自動裁切放大上半身,後退無效。不在程式可控範圍。
  2. **軟體(本計畫處理)**:入鏡判定原本要求「所有 `requiredLandmarks` 的最小可見度 ≥ 0.5」,而深蹲/高抬腿/伏地挺身的 required 含**腳踝**。腳一出框,腳踝可見度掉到門檻下 → 整組判定關閉。

## 已實作的修正
1. **拆分概念**:新增 `gateLandmarks`(判定「看不看得到人」的核心點),與 `requiredLandmarks`(計算用點)分離。引擎入鏡判定改用 `gateLandmarks`(未指定則退回 `requiredLandmarks`)。
2. **各動作 gate**:
   - 深蹲:肩+髖+膝(去腳踝;深度只看髖 vs 膝,腳踝僅估腿長且有備援)
   - 高抬腿:髖+膝(腳踝僅用於支撐腳打直檢查)
   - 伏地挺身:**沿用完整 requiredLandmarks(含髖/踝)** — 水平姿勢容得下全身,保留塌腰防作弊(T1 定案,見下)
   - 開合跳:**不變**(量腳張開需要腳踝)
3. **可見度門檻** `visMin` 0.5 → 0.4(容忍出框但被模型估出的點;最終值見第二輪)。

### 驗證結果
- 單元測試 **34/34 全綠**(含遮擋防呆測試:遮膝蓋仍暫停)。
- 針對性驗證(乾淨深蹲 ×5):
  - 只遮腳踝:修正前 0 次 → 修正後 5 次。
  - 連膝蓋也遮:仍 0 次(取景真的不足時不誤判)。

## 第二輪:依 Codex 意見的調整(已實作)
- **Q2 門檻**:不建雙層門檻子系統(屬過度設計);`visMin` 改 **0.4**(非 0.35),並以「輔助檢查優雅降級」達成 Codex 的真正目的。
- **非 gate 點優雅降級**(核心修正):用到腳踝/髖的**輔助 block 判定**,在該點可見度 < 0.5 時**跳過該檢查**而非誤判:
  - 深蹲:腳踝不可靠 → 腿長改用「髖→膝 ×2」估算。**註:深蹲的 block 防作弊是 torso_lean,只用肩+髖(皆在 gate),不依賴腳踝 → 降級零防作弊損失。**
  - 高抬腿:支撐腳腳踝不可靠 → 跳過 no_support 檢查。驗證:坐姿代償仍被「膝高+左右交替」擋下(0 valid)。
  - 伏地挺身:**不降級**(T1 定案為 B)。改為「腿出框就暫停」,以保留塌腰防作弊;已還原先前的 sag 降級。
- **取景提示(Q1+Q3+Q5 合一)**:入鏡失敗時依「缺哪個 gate 關節點」給具體訊息(看不到膝蓋/手腕…),含「放低鏡頭/後退」與「Mac 關閉人物置中」。取代通用「請後退一步」。

### 第二輪驗證矩陣(合成低可見度)
| 情境 | 結果 | 評語 |
|---|---|---|
| 深蹲 乾淨+腳踝出框 | valid=5 | ✅ |
| 深蹲 半蹲+腳踝出框 | valid=0 | ✅ 不誤判 |
| 高抬腿 乾淨+腳踝出框 | valid=6 | ✅ 不被誤擋 |
| 高抬腿 坐姿代償+腳踝出框 | valid=0 | ✅ 其他訊號仍擋住 |
| 伏地挺身 乾淨(全身可見) | valid=5 | ✅ |
| 伏地挺身 塌腰(全身可見) | valid=0(invalid=5) | ✅ 塌腰被擋下 |
| 伏地挺身 乾淨+下半身出框 | valid=0 | ✅ T1=B:暫停(保留 sag 防作弊) |
| 開合跳 腳踝不可見 | valid=0 | ✅ 正確暫停 |

## 共識結論(Codex 第二輪 REVIEW: APPROVED)
**T1. 伏地挺身 sag → 採選項 B(已實作)**:把髖/踝留在 pushup 的 gate(沿用完整 requiredLandmarks),腿出框就暫停而非無聲關閉 sag 檢查。理由:伏地挺身是水平姿勢、自然容得下全身,保留塌腰防作弊比多容忍取景更重要(評審肉眼看得出塌腰被誤算)。已還原先前的 arms-only gate 與 sag 降級。

**T2. 高抬腿 no_support 降級 → 維持(可接受)**:腳踝不可見時跳過支撐腳檢查;坐姿代償仍被「膝高+左右交替」擋下(矩陣 valid=0),主要作弊路徑已覆蓋,不需再加系統。

## 待決:什麼是「最適合使用者」的偵測/引導模式?(原始 Q1-Q5,部分已於第二輪定案)
針對 Demo 場景(評審、筆電、小空間、首次使用),要拍板以下選項:

### Q1. Center Stage 無法用程式關閉,怎麼處理?
- 候選 A:只在文件/口頭提醒評審手動關。
- 候選 B:偵測到「持續只有上半身可見(gate 連續 N 秒失敗,且肩可見)」時,跳一次性提示卡:「請關閉 Mac 控制中心的『人物置中』」。
- 取捨:B 較貼心但要寫偵測啟發式,可能誤報。

### Q2. `visMin` 從 0.5 降到 0.35 是否過鬆?
- 風險:低光/遮擋時可能讓品質差的估計點通過,增加誤判。
- 是否該保留 0.4 折衷?或對不同動作分別設定?

### Q3. 即時取景輔助(取代單一「請後退一步」)
- 具體指出缺哪個 gate 點:「看不到膝蓋,把鏡頭放低」「往後退一步」。
- 成本中等;對首次使用評審價值高。要不要納入這次?

### Q4. 開合跳在小空間必然失敗(需腳踝)
- 是否在 Demo 預設/建議用深蹲(下肢只需到膝),把開合跳標為「需較大空間」?
- 或新增一個「純上半身」示範動作確保任何取景都能展示?

### Q5. 相機請求目前 1280×960(橫向 4:3)
- 站姿全身偏高,橫向易切到頭/腳。是否改偏直幅、或在說明頁提示「把筆電放低、後退」?

## 不變更範圍
- 不動核心計次/防作弊狀態機與計算邏輯。
- 不動開合跳的腳踝需求。
- 不引入打包工具/框架。
