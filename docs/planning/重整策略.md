## 三、應該重做的 UI / UX

**只重做三處＋一批接線，其餘頁面「收斂」不重畫：**

1. **App 首屏 →「今日」層**（新東西）：今日任務卡＋目標環＋連續天數＋單一大 CTA「開始訓練」；島/型錄退為導覽。
2. **結算頁 → 兩幕式獎勵儀式**：第一幕成績單（保留現有）＋第二幕「金幣飛入島嶼／解鎖進度前進」演出＋「去蓋房子」直達鈕。
3. **訓練清單首屏**：從「型錄」改為「今日推薦置頂＋型錄其下」。
4. **接線或收起（不算重做，算還債）**：難度→引擎係數、三色模式→回饋渲染、每日/週目標→今日層與健康頁；OAuth 假按鈕 Demo 版收起。

明確**不重做**：訓練 HUD、健康圖表版面、島嶼 3D 操作、設定頁版面（除假欄位處置）。

## 七、最終重整策略結論

**結論：保留核心引擎與功能，重做「產品體驗層」——不是新架構包舊功能，更不是砍掉重練。**（若用選項語言：主方向 B「保留核心引擎、重做產品體驗」＋輔方向 A「僅三處 UI 重做」）

**原因：**
1. 診斷顯示斷的是**循環的第 1、4、6 步**（無任務、無儀式、無拉回）——全是體驗層工作；引擎、資料、防刷、圖表邏輯都已達（甚至超出）企劃書規格。
2. 現有架構（feature 契約＋store 單一狀態源＋純函式引擎＋CONTRACTS.md）**本來就適合往上疊體驗層**；「新架構搬遷」搬的會是零風險的地基、冒的是高風險的搬運，划不來。
3. 砍掉重練等於丟棄 34 個測試守護的防作弊引擎與兩輪互審紀錄——那是本專案在競賽中最難被抄的東西。
4. 成功關鍵：**先打通一條黃金路徑**（今日任務→取景全綠→訓練→結算儀式→金幣入島→蓋房→回今日打勾），再擴散廣度。十個補強平行開工只會再產出一批半成品；一條龍跑順，評審 5 分鐘看到的就是企劃書寫的那個產品。
